# 개인 Drive 세이브 — 보안 점검 결과

이 문서는 현재 작업 공간의 구현을 검토한 결과다. 외부 보안 감사·침투 테스트 인증은 아니며 실제 Google 계정 선택 화면까지 확인했으며 권한 동의 이후 연결 완료는 아직 검증하지 않았다.

## 데이터 흐름

```text
Mac의 게임 상태 → HTTPS → 사용자의 Google Drive/PokeTokenBar_Save
```

PokeTokenBar 운영 서버나 공유 데이터베이스는 사용하지 않는다. Google 계정이 파일 소유자가 된다. 세이브에는 게임 상태, 기기 이름과 저장 시각이 들어간다. 대화 원문·프로젝트 경로·LLM API 키·Google 로그인 토큰은 세이브에 포함하지 않는다.

## 확인한 보호 장치

| 항목 | 구현 및 확인 |
|---|---|
| 로그인 | Google 공식 시스템 브라우저 OAuth. 사용자 Google 비밀번호를 앱에서 입력받지 않음 |
| 로그인 위조 | 요청마다 PKCE S256, 무작위 state, callback 경로·Host 검증. 잘못된 state를 거부하는 테스트 |
| 요청 권한 | `openid`, `email`, `drive.file`만 요청. Drive 전체 접근 권한은 요청하지 않음 |
| 폴더 접근 | 내 드라이브 루트의 `PokeTokenBar_Save`, 본인 소유·비공유 여부 검사. 타인 소유·공유 드라이브·공유 폴더는 저장 거부 |
| 파일 접근 | 조회는 허용된 폴더 ID와 앱 파일 종류로 제한. 업로드 부모 폴더도 앱이 지정해 임의 폴더로 바뀌지 않음 |
| 통신 | Google API HTTPS 호스트만 허용. TLS 인증서 검증을 끄지 않으며 HTTP·외부 호스트·리디렉션을 거부 |
| 토큰 | 앱 내부 로그인 토큰을 앱 빌드에 넣지 않음. 인증 파일 0600, 디렉터리 0700. 공유 읽기 권한·다른 사용자 소유·심볼릭 링크 파일 거부 |
| 기록 | callback URL의 authorization code와 토큰 응답 본문을 로그에 출력하지 않음 |
| 입력 파일 | 세이브·사용량·네트워크 응답에 크기·스키마·수치 범위 제한 |
| 복구 | 교체 전 로컬 백업, 디스크 저장 후 가져오기 확인, 네트워크 응답 유실 후 재시도 상태 유지 |
| 충돌 | 동시 편집은 선택을 요구. 아이템과 사용량을 임의로 합산하지 않음 |
| 정리 | 오래된 자체 백업은 휴지통으로 이동. 다른 기기 파일·폴더·세이브를 영구 삭제하지 않음 |
| 권한 변경 | 이전 `drive.appdata` 토큰은 새 폴더 권한으로 자동 간주하지 않고 다시 로그인하도록 요구 |

## 남아 있는 한계

1. **Google Drive 계정 보안에 의존한다.** 사용자가 폴더나 파일을 공유하면 공유 대상이 읽을 수 있다. 후속 동기화에서 공유 폴더를 발견하면 중단하지만 외부의 공유 변경과 파일 업로드를 하나의 원자적 작업으로 묶을 수는 없다.
2. **앱 자체의 종단 간 암호화는 없다.** 세이브는 사용자가 확인·다운로드할 수 있는 JSON이다. Google의 저장소 보호와 HTTPS를 사용한다.
3. **현재 Mac 토큰은 Keychain이 아닌 권한 제한 파일이다.** 다른 OS 사용자는 읽을 수 없도록 하지만, 같은 사용자 권한으로 실행되는 악성 프로그램까지 방어한다고 보장하지 않는다. 공개 배포 전에는 네이티브 Keychain 연동과 안정적인 코드 서명을 추가 검토해야 한다.
4. **실제 연결 완료 검증이 남았다.** 클라이언트 ID를 등록하고 Google 공식 계정 선택 화면 진입을 확인했다. 권한 동의 이후 실제 Drive의 폴더 생성·소유권·권한 응답, 토큰 갱신은 실계정에서 확인하지 않았다. Testing 상태의 토큰 만료 정책도 확인해야 한다.
5. **Google Drive의 `drive.file`은 앱 파일 단위 권한이다.** Google 자체가 폴더 ID 하나로만 권한을 제한하는 모델은 아니다. 앱 코드는 대상 폴더로 조회·쓰기를 추가 제한한다.

## 사용자에게 필요한 정보

앱 설정에 넣을 값은 개발용 **OAuth 클라이언트 ID**다. Google 계정 비밀번호나 refresh token이 아니다. 앱 등록은 개발자가 한 번 하고 일반 사용자는 Google 로그인 버튼만 사용한다.

사용자는 권한 동의 화면에서 Drive 전체 접근이 아니라 앱이 사용하는 특정 파일의 저장·관리 권한인지 확인하고, 본인의 Google 계정으로 로그인한다. 실제 동의와 계정 선택은 사용자가 수행한다.

## 검증 근거

Python 테스트는 개인 폴더 생성·재사용, 폴더 밖 업로드 방지, 공유 폴더 거부, 중복 루트 처리, 목적지·리디렉션 차단, 토큰 파일 권한, 초기 자동 백업, 응답 유실, 충돌과 휴지통 정리를 검사한다. 네트워크와 OAuth callback은 모의 전송으로 검증했다.

Swift 테스트는 사용자 파일 선택 없는 앱 설정 로그인, 클라우드 세이브 적립 기준값·난이도 이전, 로컬 변경 보호, 입력 크기 제한, 번들 helper 경로 및 설정 화면 렌더링을 검사한다. 테스트 통과를 실제 계정 연결 완료나 취약점 부재의 증명으로 해석하지 않는다.
